# Room-Level Synthetic AC Telemetry Generator (PS 3.2)

> **CRITICAL TRANSPARENCY NOTICE**:  
> **All room-level telemetry, occupancy counts, and anomaly labels generated by this package are SYNTHETIC.**  
> While the diurnal curves, night baseload ratios, and outdoor ambient temperature dependencies are anchored on real measured chilled-water meter telemetry from the ASHRAE Great Energy Predictor III competition dataset (Site 2, Building 173/253/229), all individual room disaggregations, computer vision headcount readings, set temperatures, and operational anomalies are synthetically generated models.

---

## 1. Package Overview
This package is a self-contained, reproducible simulation and data synthesis engine designed for the **PS 3.2 AI-Powered Campus AC Energy Optimization** project.

It converts whole-building chilled-water cooling profiles ($\text{kW}_{\text{th}}/\text{m}^2$) into individual room-level AC compressor power draw ($\text{kW}_{\text{electrical}}$), indoor room temperatures, CV camera occupancy estimates, and ground-truth anomaly events.

## 4. Output Datasets & Field Contracts

All outputs are saved to `synthetic_data/output/` in both Apache Parquet and CSV formats:

### `ac_telemetry.parquet`
- Matches backend database model `ACTelemetryModel`.
- Columns:
  - `id`: Unique telemetry identifier (`tel-{unit_id}-{timestamp}`).
  - `room_id`: Room code (e.g. `eng-101`).
  - `ac_unit_id`: AC unit code (e.g. `ac-eng-101-1`).
  - `timestamp`: Hourly timestamp (YYYY-MM-DD HH:MM:SS).
  - `power_kw`: Electric power drawn by AC unit ($0.03\text{ kW}$ standby to rated maximum).
  - `set_temp_c`: Temperature setpoint ($^\circ\text{C}$).
  - `room_temp_c`: Simulated indoor room temperature ($^\circ\text{C}$).
  - `outdoor_temp_c`: Outdoor ambient temperature ($^\circ\text{C}$, from Site 2).
  - `occupancy`: Headcount detected by room CV camera.
  - `on_off_status`: Operational status (`ON` or `OFF`).
  - `scheduled_hours`: Boolean flag indicating if room has a timetable booking.

### `occupancy_readings.parquet`
- Matches backend database model `OccupancyModel`.
- Columns: `id`, `room_id`, `timestamp`, `headcount`, `confidence`, `is_synthetic`.

### `weather.parquet`
- Matches backend database model `WeatherModel`.
- Columns: `id`, `timestamp`, `outdoor_temp_c`, `relative_humidity`, `solar_irradiance_wm2`.

### `ground_truth_labels.parquet`
- Matches backend database model `GroundTruthLabelModel`.
- Strictly segregated ground-truth labels for evaluating anomaly detection models:
  - `id`, `room_id`, `ac_unit_id`, `anomaly_type`, `start_time`, `end_time`, `severity`.
  - Anomaly Types: `after_hours`, `ghost_cooling`, `overcooling`, `early_start`, `possible_leakage`.

## 5. Mathematical & Physical Assumptions

1. **Building Thermal Anchoring**:
   $$\text{Load Intensity } I_{\text{bldg}}(t) = \frac{E_{\text{bldg, chilled\_water}}(t)}{A_{\text{bldg}}} \quad [\text{kW}_{\text{th}}/\text{m}^2]$$
2. **Room Cooling Demand**:
   $$Q_{\text{room}}(t) = I_{\text{bldg}}(t) \cdot A_{\text{room}} \cdot \alpha_{\text{room\_type}} + N_{\text{occ}}(t) \cdot 0.10\text{ kW}_{\text{th}}$$
3. **Electric Power via Temperature-Dependent COP**:
   $$\text{COP}(T_{\text{outdoor}}) = \text{clip}\Big(3.5 \cdot \big[1 - 0.018 \cdot (T_{\text{outdoor}} - 35)\big], 2.2, 4.5\Big)$$
   $$P_{\text{electric}}(t) = \frac{Q_{\text{unit}}(t)}{\text{COP}(T_{\text{outdoor}})}$$
4. **CV Headcount Camera Noise**:
   $$\text{Headcount}_{\text{CV}} = \text{clip}\big(\text{round}(N_{\text{actual}} + \mathcal{N}(0, 1.2)), 0, \text{Capacity}\big)$$
